## 1. Что хочет юзер (резюме ТЗ + доп-требования)

### Из ТЗ (Project Loom v0.1 — кодовое имя, не бренд)

**Концепция:** дружелюбное ядро-оркестратор + магазин подключаемых модулей. Каждый модуль — изолированный навык с собственной памятью, инструментами, прокачкой L0→L4. Модуль СО ВРЕМЕНЕМ становится «личным экспертом» — это главный дифференциатор от ChatGPT/Claude/GPTs.

**Ключевые принципы:**
- Friendly-first (без жаргона, единый персонаж)
- Модульность (контракт `module.yaml`, изолированные песочницы)
- Мульти-LLM по силе (Claude / GPT / Grok / Perplexity, роутер выбирает)
- Самообучение через RAG + Adaptive System Prompts (НЕ fine-tuning базовой LLM)
- Кросс-платформенность (web + mobile)
- 152-ФЗ compliance, права на экспорт/удаление

**Архитектура (4 слоя):**
1. **Интерфейсный** — Frontend / Mobile / API
2. **Оркестратор (ядро)** — Intent Recognition · LLM Router · Context Manager · Memory Hub · Personality Layer · Permission Broker · Action Logger · Module Marketplace API
3. **Слой модулей** — изолированные навыки
4. **Слой данных** — Postgres + векторная БД + S3 + Redis

**LLM Router (раздел 4 ТЗ) — критический компонент:**
- 4 паттерна: Pipeline / Parallel ensemble / Verify / Specialist routing
- Cost-aware (дешёвые для простого, флагманы для сложного)
- Семантический кэш (экономия 30-50%)
- Бюджеты по тарифу
- Health-checks + fallback + circuit breaker

**Прокачка модулей (раздел 5):**

| L | Название | Что умеет | Условие |
|---|---|---|---|
| L0 | Базовый | Универсальные ответы | По умолчанию |
| L1 | Знакомство | Знает базовые факты о юзере и задаче | 5-10 взаимодействий + onboarding |
| L2 | Адаптация | Подстраивается под стиль, использует терминологию юзера | Подключён источник + 30 взаимодействий |
| L3 | Эксперт | Действует проактивно, замечает аномалии | Накоплена база + 4+ недели регулярного использования |
| L4 | Автономия | Выполняет рутинные действия без подтверждения | Явное разрешение юзера + история без ошибок |

**Память (3 уровня):**
- Глобальный профиль (имя, тон, предпочтения) — read всеми модулями
- Модульная (изолированная) — read/write только своим модулем
- Эпизодическая (история диалогов) — оркестратор + текущий модуль

**MVP-модули (ТЗ предлагает):** Почта (Gmail), Календарь, Питание, Заметки.
**1.0 (бизнес):** Яндекс.Директ, CRM, аналитика.
**2.0:** SDK для маркетплейса третьих модулей, L4-автономия, командные модули.

**Тарифы:** Free (1-2 модуля, L0-L1) → Pro (все базовые, L0-L3) → Business (бизнес-модули, L4, мульти-аккаунт).

### Доп-требования от юзера (2026-05-16 в чате, не в ТЗ)

1. **Мобильное приложение с упрощёнными вкладками** — install из главного окна
2. **ИИ агент = текстовое управление как в Telegram** (главный экран — чат)
3. **Бизнес решения помельче** в мобильном
4. **Чат-боты минимальный стек управления** в мобильном (только on/off, метрики)
5. **Сайты не делаем** в мобильном (только с компа)
6. **КП — только шаблоны** в мобильном
7. **Весь функционал доступен с приложения**, включая пополнение баланса
8. **API соц-сетей** — X, YouTube, Instagram + RU-альтернативы

## 2.1. UX-флоу страницы «🤖 ИИ Агенты» (решение юзера 2026-05-16)

Главное отличие от старого workflow-конструктора — **диалоговое создание** агента. Юзер не заполняет формы и не строит граф. Он жмёт «Создать» → выбирает способ управления → попадает в чат с агентом-конструктором, который сам подбирает модули и расписания через диалог.

### Главный экран `/agents` (заменяет старый agents.html)

```
┌─────────────────────────────────────────┐
│  🤖 Мои агенты              [+ Создать] │
├─────────────────────────────────────────┤
│  📱 SMM-агент Instagram                 │
│     8 постов/нед · модули: 📝 ✍️ 🎨    │
│     ⏰ Каждый день 09:00                │
│     [Открыть чат]  [⚙ Настройки]       │
├─────────────────────────────────────────┤
│  💬 Автоответчик клиентов               │
│     🟢 Активен · 23 диалога сегодня     │
│     [Открыть чат]  [⚙ Настройки]       │
└─────────────────────────────────────────┘
```

Пустое состояние: большая CTA «Создать первого агента» + **3-4 шаблона** (SMM-агент / Помощник по почте / Автоответчик / Личный аналитик) для быстрого старта.

### Создание агента (4 шага)

**Шаг 1. Выбор способа управления** (из 4):
- 💬 **Чат** — общаюсь сам, говорю что делать (по умолчанию)
- ⏰ **Расписание** — работает по cron («каждый день в 9:00», «по понедельникам»)
- 📨 **Триггеры** — реагирует на события («новое письмо», «упоминание в TG», «лид в CRM»)
- 🔄 **Гибрид** — несколько способов вместе

**Шаг 2. Сразу чат с агентом-конструктором** (никаких форм). Конструктор задаёт уточняющие вопросы, сам подбирает модули из каталога 48 ролей + новые модули из roadmap.

Пример диалога:
```
Конструктор: Привет! Что хочешь чтобы агент делал?

Юзер: Хочу пост в 9 утра каждый день на тему стройки в моём блоге ВК

Конструктор: Понял — контент-агент с автопостингом в ВК.
             Уточню три вещи:
             1. Какие посты — текст / с картинкой / с видео?
             2. На какой странице ВК? (вижу одна подключена, использовать её?)
             3. Сколько подготовить заранее — на 7 дней / месяц / по одному?

             (отмечу: подключу модули ✍️ Копирайтер, 📅 Календарь, 📱 VK-постинг)
```

**Шаг 3. Подтверждение «итоговой карточки»:**
```
✓ Подключатся модули: ✍️ Копирайтер, 📅 Календарь, 📱 VK-постинг
✓ Расписание: каждый день 09:00 МСК
✓ Тема: стройка
✓ Цена: ~15 ₽/день (контент с картинкой)
[Запустить]  [Изменить через чат]
```

**Шаг 4. Агент работает в фоне** — юзер получает push (когда сделаем) / видит в карточке статус / может в любой момент зайти и проверить.

### Два режима общения с агентом ПОСЛЕ создания

| Режим | Когда срабатывает | Пример |
|---|---|---|
| **Команды** | Юзер даёт задачу на лету | «А сделай ещё пост про новый ГОСТ» / «Стоп публиковать на выходных» |
| **Настройка** | Юзер меняет конфиг диалогом | «Перенеси на 10 утра» / «Добавь модуль аналитики постов» / «Отключи Копирайтер» |

Агент **сам различает** что хочет юзер (команда vs изменение spec) через LLM-классификатор и либо выполняет, либо меняет spec и подтверждает.

### Альтернативный путь: проактивное планирование

```
Юзер:   «Сделай контент-план на месяц по моему бизнесу»
   ↓
Агент:  создаёт план (30 постов с темами/датами)
   ↓
Юзер:   апрувит план одной кнопкой
   ↓
Агент:  сам идёт по плану в фоне, генерирует и публикует
   ↓
Юзер:   получает push «опубликован пост N»
        либо может зайти и посмотреть в любой момент
```

### Что это меняет в архитектуре

3 новых компонента:

1. **Agent Builder** — отдельный «агент-конструктор» (агент-чтобы-делать-агентов). Его job = диалог о создании. Tools: `add_module` / `set_schedule` / `set_trigger` / `save_agent_spec` / `show_summary_card`.

2. **Spec-mode классификатор внутри агента** — после создания агента, каждое сообщение юзера сначала классифицируется: команда vs изменение настроек. Простая стадия в pipeline.

3. **Agent Spec модель** — JSON-конфиг агента: `modules[]`, `schedule (cron string)`, `triggers[]`, `goals`, `system_prompt`. Хранится в расширенной таблице `Agent` (заменит/расширит существующий `AgentConfig`). Расписания регистрируются в существующем [scheduler](../../server/cron/), триггеры — в [webhook router](../../server/routes/webhook.py).

### Что переиспользуем (не строим с нуля)

- **48 ролей из [registry.py](../../server/agents/registry.py)** — Agent Builder подбирает из них модули
- **`delegate` tool из [agent_runner.py](../../server/agent_runner.py)** — агент может вызвать суб-агента из своих модулей
- **[scheduler](../../server/cron/)** — для cron-задач агента
- **[webhook router](../../server/routes/webhook.py)** — для триггеров
- **[chatbot_engine](../../server/chatbot_engine.py)** — для каналов (TG/VK/Avito/MAX/WhatsApp)
- **Streaming SSE из solutions_orchestra** — для прогресса в карточке агента

## 3. Мобильное — только PWA (решение юзера 2026-05-16)

**Native приложение НЕ делаем.** Юзер прямо сказал: «приложение мы не делаем пока отдельно, мы адаптируем как приложение через сохранение быстрой ссылки на рабочий стол». То есть:

- ❌ Никакого React Native, Apple Developer ($99/год), Google Play ($25), App Store submission
- ✅ **PWA** — `manifest.json` + service worker + meta-tags + Add-to-Home-Screen
- ✅ Юзер на iPhone: «Поделиться → На экран Домой» → иконка как нативное приложение, fullscreen
- ✅ На Android Chrome: автоматический баннер «Установить» через `beforeinstallprompt`
- ✅ Та же web-страница aiche.ru — просто с правильным манифестом и адаптивной вёрсткой

**Push в MVP не делаем** (юзер: «потом добавим»). В проекте уже есть VAPID-инфраструктура ([модуль 17](17-push.md)) — её можно расширить когда понадобится. Работает в Android PWA из коробки, в iOS PWA — с iOS 16.4+.

### Упрощённые вкладки (адаптивная вёрстка для моб)

```
🏠 Чат           ← главный (текстовое управление Loom-агентом)
💼 Решения       ← Бизнес-решения (компактные карточки)
💬 Боты          ← список ботов, on/off, метрики (без редактора)
📄 КП            ← выбор шаблона → заполнить → отправить (без сложного редактора)
📚 Знания        ← Knowledge Hub (все категории, поиск)
💰 Кошелёк       ← баланс + пополнить (Apple Pay / СБП)
👤 Профиль       ← настройки, привязки соц.сетей, выход
```

**НЕ будет в моб:**
- Конструктор сайтов (только с компа)
- Canvas-редактор workflow
- Админка
- Сложные настройки шаблонов КП (только выбор готового)

### ✅ Фаза 1 (частично) — Module Runtime + прокачка модулей (2026-05-16)

После архитектурной правки (singleton-агент + модули) добавлено:

- ✅ **Singleton-агент** (один Agent на юзера, get-or-create в роутах)
- ✅ **AgentModule** таблица: slug + level (L0-L4) + interaction_count +
  module_memory + custom_settings + schedule_cron + is_enabled
- ✅ **Memory Hub** в `Agent.profile_json` — что агент знает про юзера
  (имя, сфера, тон, цели, факты с timestamp). Заполняется в онбординге.
- ✅ **Personality Layer** в `Agent.personality_json` — display_name, icon,
  voice, addon_prompt. Поверх всех LLM-вызовов.
- ✅ **Module Runtime** ([server/agent_builder.py](../../server/agent_builder.py)::invoke_module):
  - Подмешивает Memory Hub + персональную память модуля + custom_settings
    в `system_prompt` модуля из AGENT_REGISTRY
  - Модуль может вернуть `[LEARNED: ...]` маркеры — сохраняются
  - LLM Router выбирает model по типу модуля (smm→creative, lawyer→deep_analysis)
- ✅ **Прокачка L0→L3** (compute_module_level):
  - L0→L1 при 5+ взаимодействий + agent.status=active
  - L1→L2 при 30+ взаимодействий + 3+ выученных заметок
  - L2→L3 при 200+ взаимодействий + 20+ заметок
  - L3→L4 — только через явный API (юзер сам разрешает автономию)
- ✅ **Personal Builder** action `invoke_module` — Че сам делегирует
  подключённым модулям через JSON-action в его ответе. UI рисует
  отдельное сообщение `role=tool` от модуля с уровнем + level-up badge.
- ✅ **LLM Cache** ([server/llm_cache.py](../../server/llm_cache.py)) — exact-match
  hash-кэш с TTL, daily cleanup через scheduler. Не кэширует
  streaming/attachments/temperature>0.5/«сейчас». Подключён в LLM Router.
- ✅ **Mobile drawer** — sidebar становится выезжающим на <980px,
  toggle-кнопкой 🧩 в header с counter модулей.

**Что юзер может СЕЙЧАС:**

4. В чате: «напиши пост про X» → Че делегирует copywriter → отдельная
   синяя плашка от модуля с ответом + chip L0
5. После 5 заданий модулю — авто-прокачка до L1 (visual badge ⬆)
6. Модули учатся через [LEARNED:...] маркеры — память персональная

**Что НЕ реализовано (Фаза 1 продолжение):**

## 8. Что НЕ делаем (zone of avoidance)
